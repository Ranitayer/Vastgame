# Vastgame desktop rules

## Architecture and scope

- Use Tauri 2, Svelte 5, TypeScript and custom CSS. Keep Rust thin; reuse the Vastgame CLI for lifecycle, accounts, games, quotes, scoring and saves.
- Keep Home composition in `src/home/`, reusable rig components/data in `src/hosts/`, game components/data in `src/library/`, shared controls in `src/components/`, and one launch controller in `src/session/`. Keep tab definitions in `src/navigation.ts`; no router, extra database, UI framework, plugin or service is needed.
- Home, Sessions and Settings are implemented. Standalone Hosts and Library pages and tabs are removed. Billing remains empty until requested. The game-settings gear is intentionally inactive.
- Fetch catalogs on first activation and explicit Refresh. Host browsing runs one active request and keeps only the latest queued game choice. Use the shared game catalog for Home and size hosts for the selected game. No background polling or requests on slider movement. Window and scroll behavior use native events and observers.
- Rust exposes fixed backend commands only. Linux uses the installed CLI; Windows uses the Vastgame WSL distribution and user. Never expose arbitrary shell execution, filesystem access, launch arguments, raw manifests, credentials or save policies to the webview. Grant only required Tauri capabilities.

## Theme and common layout

- Use the supplied palette below, with `#151d28` as the default surface and `#884b2b` as the accent. Keep semantic tokens in `src/theme.css`; components consume tokens. Original Steam artwork and local country-flag colors are permitted semantic artwork.
- Follow Material You: rounded surfaces, restrained tonal hierarchy, readable text and centered controls. Use system fonts and inline SVG icons. No remote fonts, runtime icon CDN, blur, animated background or permanent idle animation.
- Every page edge, section gap, card-to-card gap and panel inset uses `--page-margin`: 24px normally, 12px at heights up to 800px. Change this once at the root. Game cards alone use compact equal `--game-card-inset` padding of 10px; do not inflate it with page spacing.
- `HomePage.svelte` owns the filters-to-content gap through the root margin. `SearchRefresh.svelte` owns search and icon refresh. Home has no heading or result-count row; covers, host pills and the game panel begin one shared margin below their controls.
- `Button.svelte` owns ordinary control sizes, pill/circle radii, disabled states, color fades and reduced motion. Reuse tonal/plain/outline/inverse/tab/surface variants, neutral/blue/red/green action tones and small/normal/large sizes. Buttons, cards and covers never zoom.
- `Dropdown.svelte` owns every themed dropdown. Use neutral surfaces, 4px between choices and accessible keyboard selection. Small lists show every choice; large lists keep search above a viewport-bounded scrollable list. No page arrows or counters. Preserve mouse wheel, touch and keyboard navigation with hidden native scrollbars. Reuse the shared popup placement.
- `Popover.svelte` owns notices, confirmations and dropdown placement. It portals to the body and clamps to viewport margins. Notices and confirmations appear to the right of their button, falling back to the left when space is insufficient; dropdowns open vertically with an upward option. All close on outside click or Escape. Notices appear directly without a notice button; notices and confirmations fade away after two seconds. Dropdown menus remain open for selection; destructive Settings confirmations reuse the persistent dialog mode and restore focus on dismissal. Preserve reduced motion and detailed errors in Logs.
- `DetailsPanel.svelte` owns Home and Sessions' shared right-side panel surface, rounded corners, inner cards and optional unified inset. Both columns use `--details-panel-width`; never build a separate left-side panel or duplicate these surface styles.
- `ScrollArea.svelte` provides a passive indicator centered in the card/panel gutter. No pointer, selection or hover behavior. Preserve wheel, touchpad, touch and keyboard scrolling.
- Keep compact tabs centered in the full title bar with balanced side columns. Navigation order: Home, Sessions, Billing, Settings. Tab hover uses `#394a50`, selected tabs use the accent. Keep window controls separate; preserve icon labels and keyboard navigation on narrow windows.
- Minimum native window size is 600×600. Maximized/fullscreen windows fill their bounds with square corners, no border or outer gap. Windowed mode restores rounded corners. Frame changes are instant; never animate native bounds or webview resizing.
- Preserve visible focus, accessible names, keyboard access, contrast and reduced motion. Adapt shared styles to OS scaling; isolate platform-specific behavior.

## Settings

- `settings/SettingsPage.svelte` keeps Streaming and Hosts & Region adjacent without page scrolling. Reuse Dropdown, Button, Range, NumberField and Toggle. Preserve the shared page margin for card edges/gaps; fit compact row spacing and control heights to the actual available page height, including the 600×600 native minimum. Streaming fills the left column above Sensitive settings, whose bottom aligns with the unified page margin. Sensitive actions gain comfortable padding in taller windows. Use each box's width to size label/control columns without wrapping actions or losing margins. Descriptions sit on the same line as headings, aligned right, with full hover text when shortened. Keep bitrate value and slider beside each other. Never clip controls.
- Shared theme Save and Reset buttons sit directly right of the Settings tab while Settings is active. Reset immediately restores and persists streaming/host defaults, without changing credentials, game saves, templates or VMs. It saves all settings, says Saved after success, and returns to Save on the next draft change. Keep detailed save errors in the page without footer descriptions or inactive-limit hints. Validate both groups before writing; roll back reported write failures. Streaming edits codec, decoder, YUV 4:2:0/4:4:4, display mode, native/custom frame rate and resolution, frame pacing, VSync, stereo/5.1/7.1 audio, and 0–500 Mbps bitrate (zero means Moonlight default). Persist through the fixed native settings command into the same stream.json consumed by CLI and native Moonlight on the next connection. Preserve all other Moonlight options by merging the permitted option patch. Saving never reconnects or rents. Toggle buttons never retain a selected outer background; only the switch track/thumb reflects its on/off state.
- Hosts saves country, preferred GPU, an inactive spending-limit value in $0.10 steps, verified-only, and minimum download/upload Mbps, VRAM GB and RAM GB. Validate and atomically save private host_preferences.json; zero minimums add no filter. The spending-limit value must not enforce a budget or stop a session yet.
- The shared backend ranker applies verified/minimum filters and scores country-distance preference (up to 15 points) and preferred GPU (+5 points). Use bundled public-domain country locations for all ISO countries/territories; proximity is a geographic estimate, never measured latency. Country/GPU preferences affect Best value rather than excluding other countries/GPUs. Keep compatibility, exact quote and save protections intact. Saving invalidates the Home host catalog; its existing request queue refreshes once on returning to Home, never on input movement.

- Sensitive settings sits directly below Streaming, with compact dark action rows and shared 32px buttons. Its red actions reuse Button and the shared Popover confirmation before irreversible execution. Detailed results and errors use the persistent shared popup so they do not enlarge the fixed Settings layout. Force shutdown targets only canonical Vastgame-labelled account instances, including retained/provisioning rigs; cancel only owned workers, block replacement rentals, and reuse the exact ID/label provider-verified force stop without backups. Show per-rig failures and confirm absence before reporting success. History deletion erases saved summaries and compressed logs; retain only hidden identity tombstones to prevent legacy imports and late writers resurrecting erased history or losing live rig control. New rental IDs record normally. Never run these actions in development validation.

## Host data

- CLI and app share `host_offer_query`, `rank_host_offers` and `eligibility.jq`. Never add a desktop GPU whitelist, architecture rule, history exclusion or frontend scoring formula. Browsing has no price, region or 15-result shortlist cap; the provider request ceiling is 10,000 offers. Changing browse filters must not change CLI defaults, accounts or VMs.
- Continent choices come only from fetched offers and the local country map. Unknown locations stay under All continents. Local sorting supports lowest price, highest price and Best value; value consumes the backend scorer with saved stream targets and game history.
- Home's selected game invokes `hosts --json --game ID` for disk sizing and scoring. Filter known launch requirements only; do not invent per-game minimum GPU/RAM needs or promise FPS from estimated scores.
- App owns one session-only rig choice. Another choice replaces it; Refresh updates or clears it. Selection alone never rents. `CountryLabel.svelte` uses lazy local MIT-licensed flag SVGs.

## Home

- Keep three columns beside each other: a wider scrollable Library with centered shared search/refresh and three smaller game cards per row, a scrollable stack of host pills, and the existing game panel with a larger selected-rig pill spanning its full width above it. Use the root margin for column gaps and panel spacing.
- Reuse `GameCard`, `GameDetails`, `SelectedRig`, `RigSummary`, `HostSpecs` and `ScrollArea`; do not copy launch controls, specs, logs or artwork loaders. Covers fit their Home grid cells, capped at 200px card width including the compact inset.
- Host pills show left-aligned flag, GPU, VRAM, download speed and hourly price, without disk space. A separate circular arrow on the right expands/collapses four shared specification cards in a 2×2 grid (CPU, RAM, download, upload) inside the same continuous pill surface, with no animation or second panel. The selected-rig summary above the game panel stays centered and retains disk space. Keep host text clipped within its own area so it cannot overlap the arrow. The whole pill is a shared tonal selection button and brightens to the same neutral selected color as dropdowns; it has no Select label or separate Select button. Selection remains independent of expansion. Never nest the arrow inside the selection button.
- Host-list hourly prices, including /h, are bold and use `--price: #75a743`. Other rig summaries retain their normal text color.
- Host pill summaries use their own text area's container width: hide download speed and its separator at 340px or below, then VRAM and its separator at 250px or below. Preserve flag, GPU and full price/h; full values stay available in the accessible label, hover title and expanded details. These rules must not alter the selected-rig summary elsewhere.
- During Home startup, `RigStatus.svelte` replaces the top selected-rig content with the shared startup progress in one horizontal row: stage, activity or transfer measurements, and fresh ETA. Never stack these inside the pill; clip long text without wrapping. Hover or keyboard focus shows rig information; leaving restores progress. The slot and selected-rig pill use `--button-size`, matching the dropdown height and aligning the game panel's top with the first host pill. Preserve the full panel width and omit the duplicate progress card inside Home's game panel. Use the launch-time rig snapshot so a later selection cannot describe the wrong launch; do not invent rig details after restoration.
- Keep elapsed session time at the right of that same pill, including during hover. Start at Play, persist its timestamp in the existing launch job and restore it on reopening. Reconnect, game exit and failed shutdown never reset or stop it. Freeze only on confirmed provider absence; attempts that never rent stop on their preflight failure. This includes startup and shutdown time and is not an invoice or billing duration. Only the visible running timer updates once per second; it makes no provider requests.
- Home GPU and continent filters sit above the host list. The shared price/value ranking dropdown opens upward beside the shared price slider at the bottom. All filters are local; Best value consumes the existing backend score. Never invent a separate tier formula or trigger requests for local filtering.
- `hosts/catalog.svelte.ts` owns one request queue. Home sizes offers for the chosen game using the same backend. Render all matching host pills without a visible-list limit or Show more. Game covers retain 48-entry batches with Show more.

## Games

- Read `vastgame list --json`. `game_identity.py` resolves presentation-only Steam IDs/names from explicit overrides, manifest IDs, and the bundled Ludusavi title/install/executable index. Unknown games use bounded public Steam search on first visible artwork load; only unique exact normalized matches are accepted. Cache positive identities for 30 days with at most 128 files. Local `library.json` overrides remain optional; never rewrite immutable manifests for labels or use a PC-specific list of games.
- Artwork requests identify the local game, resolve its Steam identity, then use fixed public Steam URLs and a 64MiB backend disk cache. Return only artwork and sanitized presentation identity to the frontend; share that identity with details/reviews. Keep two active frontend requests and visibility loading. Release offscreen card images; bound the completed frontend cache to 32 entries or 8MiB of encoded characters. Failed/partial metadata is retryable on Refresh; successful metadata is limited to 128 entries with a 24-hour lifetime. Descriptions and real review summaries are plain text; never inject remote HTML.
- Home game cards fit their three-column grid up to 200px wide, with equal 10px card inset and a neutral hover/focus background fade. Cards keep their natural height and never stretch to fill a grid row. Cards have no visible title or footer; preserve the full game name in their accessible label and hover title. The inactive settings gear is a separate shared circular surface button inside the cover's bottom-right corner, using app-background color with a light icon. Never nest the gear button inside the cover button. Pointer bounds and images stay static; use `GameArtwork.svelte`, not a second cover component.
- The panel does not scroll. Banner images preserve both sides with contain sizing, top alignment, an aspect-ratio-based responsive height cap and a fade ending at the image bottom. The accent review pill sits beside the title, centered, without a star. Preserve full descriptions and review counts in accessible content/hover text when compacting.
- Show only About text and download size on the right of its heading. Omit developer/publisher cards, package status, version, installed size, runner and NVIDIA compatibility.
- Banner Play uses `PlayButton.svelte` and the shared inverse button: a 48px light circle with dark triangle, inverted hover colors, no zoom, and a rotating arc only while starting.
- `GameLogs.svelte` is closed by default and toggled by a neutral Logs button at bottom-left, with no adjacent status button. Switching games closes it; a retained rig shows that rig's activity. Reserve its remaining bottom slot even while closed, separated from information by `--page-margin`; toggling must not resize the banner or upper content. `session/logs.ts` formats full redacted console output without whitelists, summaries, quote rounding or duplicate suppression. Preserve original messages, numeric fields, progress lines and traceback indentation. Show only full-width message text in compact monospace rows using palette severity colors, without timestamps, generated severity labels or scope labels. The log viewport fills the box height, with no heading, line counter or event dividers. Use an 8px log inset. Hide native scrollbars in every log/event viewport while preserving wheel/touch/keyboard scrolling. Keep the copy icon at the top-right, with a shared circular Compress control directly to its left when the view is open. Both controls float and stay sticky above scrolling text, so it stays visible and only the first lines wrap around it, with no permanent right gutter; it copies every retained message, expands left to show Copied for one second after successful copying, then returns to its circular icon. Reuse Button and respect reduced motion. Clipboard failures must never claim success; keep an accessible error and manual-copy fallback. UI logs retain 500 redacted events batched every 100ms; full redacted output remains in bounded backend job logs.

## Launch and shutdown

- Sessions places Refresh and the shared time-range, state and sort dropdowns in one row on the left. Apply filters and sorting to the full local ledger before pagination, with one active request and only the latest queued filter choice. These controls never poll the provider. Pending launches/reconnects show Starting in blue before an instance ID exists; a known rig keeps its shutdown control during startup. Only explicit failure states show Failed. Cost estimates keep their explanation in the tooltip, without a visible estimate suffix.

- Sessions reads the durable local ledger in 48-record pages. Cards are 260px wide (1.3 times the Home cover-card limit), use the shared banner artwork, flag, Button, Notice and ScrollArea components, and show game name, observed game time, GPU/VRAM with the country flag on the same line, colored state and total charges. Banners preserve their image ratio without cropping, with a compact equal inset and rounded corners on all sides. Total cost is bold green; Connect/Reconnect use the shared blue action tone, Shutdown red, and Resume green when a retained session still reports its game running. Empty closed legacy records are omitted from listings before pagination, while their archives and unresolved/live records remain intact. Unknown historical data stays unknown; estimates and stale provider totals must be labeled. Refresh reconciles the displayed first page against one bounded charge lookup. Do not poll provider billing. Clicking a card selects it and opens a session information panel on the right. Show recorded session identity, start/elapsed time, host CPU, download and upload; omit retained time, RAM and host-health claims. Keep a Session details heading and shared circular close X at the top of every panel view; closing only clears selection and returns focus to its card. The summary never scrolls: reserve the heading space, align both information blocks to one field grid, and position the ID copy button without changing row height. Events and Logs start as compact surface-color pills with View all on the right. View all fills only the existing right-side DetailsPanel inside its shared inset; the cards and toolbar stay visible. Compress returns to the summary. Status dots appear only on cards; panel status shows text only. Events shows the separate compressed stage journal and the canonical guest startup stages used by Home, including repeated reconnect transitions, never raw console output. Seed old stage journals only from recorded milestone times and mark missing history; a stage-archive failure must not prevent saving the rental identity. Both expanded views use Home's shared LogOutput beneath the common panel heading, without an extra viewer header or card padding. Archive reads and copy use fixed validated session commands with bounded pages; never silently truncate a copy. The neutral three-dot menu copies the canonical session ID or all available archived logs; it does not belong in the Home game panel. Reuse the shared clipboard helper and LogOutput viewer, and reserve new rental IDs atomically before creation.
- Session actions prepare the exact persisted label/instance through the backend, then reuse the one launch controller for reconnect/shutdown. A destroyed session can rent again only after an explicit Connect click, from the same machine and GPU at no more than 110% of the old total hourly rate. Re-quote and validate before creation. Unknown identity, unresolved creation, another active rig or missing historical price blocks replacement. A new rental creates a new session; never revive a closed ledger record.

- `session/launch.svelte.ts` owns one launch across tabs. Only explicit Play rents the exact chosen offer. Missing selection, unavailable package, insufficient disk or another VM blocks a new rental.
- `offer_quote.py` owns shared quote validation for preflight and CLI startup. Search rentable single-GPU VM offers, optionally narrowed by machine, then match the returned offer ID locally. Never query bundles by returned ask ID or silently replace the offer. Distinguish timeout, failed lookup, unavailable offer, compatibility, disk and price errors with typed codes and actual values.
- Size allocated storage for the chosen game, quote its total price, require a second Play click for an increase, and revalidate the approved price before creation. Keep lifecycle locking and exact VM/launch-label verification.
- `desktop_launch.py` wraps the CLI and writes private per-job identity plus bounded, redacted events. Serialize job updates; completed shutdown is terminal and late startup writes must not revive it. UI closure must never stop or destroy a VM, and must never terminate unrelated processes.
- Persist the unique rental label before creation. Restore identity on opening, explicit Refresh and window focus with one read-only provider lookup, matching the exact label/ID. Play waits for restoration; failed lookups and unknown creation must never mean an empty account or trigger replacement. Missing presentation metadata must not hide VM controls. The watcher uses inotify and owned-process exit events, with a one-second PID fallback only during active startup. It ends on completion/worker exit; no idle provider polling. Show activity as last confirmed, preserving its observation time.
- The title bar contains only the app name, tabs and native window controls. Do not add rig or launch pills there; Home's existing panel-header rig/progress pill owns that information.
- Any retained VM replaces Play with Vast Connect, including after game exit or a failed stream. Connect resumes the shared Tailscale/bootstrap/game/runtime/save readiness checks for the exact job's VM before opening Moonlight; it never rents or chooses a replacement. Revalidate its stored VM ID and label in the shared backend. Use the shared event handler and persist confirmed game status after reconnect. Keep these controls and the active rig's Logs available while browsing other games. If metadata is missing, use a minimal game-panel fallback for the known launch instead of hiding its controls.
- `ShutdownButton.svelte` owns the separate X beside Play/Connect, available as soon as the VM identity exists, including failed startup. Reuse the same 48px inverse circular button. X never greys out while a known rig exists. During normal play the first click starts protected shutdown; during startup/reconnect or after an earlier shutdown request it force-destroys the exact rig, bypassing guest access and backup. Keep an accessible force-shutdown label and a save-loss hover warning, without another confirmation popup. Repeated clicks during an active force request reuse that request. Cancel only the identity-pinned owned reconnect/startup worker, ignore its late completion and block other conflicting actions during shutdown.
- CLI stop and desktop X share `game_state.py` shutdown. Block future launches under the state lock, request the game's normal window close with its Xauthority, then use SIGTERM only for exact-prefix game processes if still active after 20 seconds. Pin and recheck process identities before signalling; never SIGKILL or terminate unrelated host/client processes. After game exit, flush the exact-prefix Wine server with SIGTERM and wait for it to exit. Require verified idle state and registry flush before backup, then verified backup before destruction. Failed exit/backup retains the VM.
- A known VM uses protected shutdown by default. An explicit second X click is the user-authorized exception: interrupt only the identity-pinned owned shutdown worker, bypass its lifecycle lock, and destroy the same provider-verified VM ID/label without SSH or backup. Serialize force requests per rig, retain local identity until provider absence is confirmed, and ignore late protected-shutdown events and writes so they cannot revive the rig. Possible game activity requires verified backup; backup failure retains the VM. Only the verified guest activity guard may authorize skipping backup; local no-request state and provider provisioning status are insufficient. Online guards freeze launches under the existing lock before examining the durable attempt marker. Publish bootstrap identity and the cancellation guard before dependency installation for new VMs. CLI stop and desktop X both use guest game identity and the same lifetime guard. Use one verified endpoint per stop: Tailscale SSH through the local agent first, then deduplicated provider endpoints; preserve label verification and report actual SSH failures. Never apply an overall probe deadline to long-running save backups. Older runtimes, missing evidence and uncertain guest state use the protected backup path.
- Startup progress uses boot, game restore, runtime preparation, save restore and game start. Show whole-task bytes/percent and ETA only from fresh measured throughput. Never invent an overall or boot ETA.
- Read-only native commands have a 75-second inner deadline, 85-second outer deadline and bounded 8MiB stdout/64KiB stderr capture. Lifecycle operations have no read timeout; event lines are bounded separately.
- Retire only stopped jobs with dead owned processes: preserve at least 24 hours, then the newest 50 for up to 30 days. Never prune unresolved rentals.
- Windows releases require a matching x64 native executable and source/checksum descriptor alongside the backend. Preserve coordinated updater rollback and private account data. Install WebView2 through the signed Microsoft bootstrapper when needed.
- Network quality never blocks startup. Local direct-route, RTT, jitter, packet-loss qualification and guest latency checks are removed, together with their history scoring and policy transport. Keep Tailscale reachability, exact peer identity, runtime integrity and save protection. The old force spelling is only a compatibility alias.
- Never perform paid launches or shutdowns during development unless explicitly requested.
